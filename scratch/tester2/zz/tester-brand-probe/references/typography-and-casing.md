# Type and casing

Source: diconium Design Guide 2024, "Typography", p.37–43.

## The family

**Campton**, by René Bieder, is the primary face, used across its full range in roman and italic.
Official fallback is **Tenorite**, then a system sans.

| Weight | Value | Use |
|---|---|---|
| Thin | 100 | Very-thin standalone key messages only |
| ExtraLight | 200 | |
| Light | 300 | |
| **Book** | **400** | **Body copy** |
| Medium | 500 | |
| SemiBold | 600 | |
| Bold | 700 | |
| **ExtraBold** | **800** | **Headlines** |
| Black | 900 | Very-heavy standalone key messages only |

Thin and Black are reserved for key messages standing on their own. Do not use them for headings in
a normal deck.

## Casing — the identity device

This is where the brand is won or lost, and it is the part an assistant will get wrong by default.

**"diconium" is always all-lowercase.** In body copy, in headlines, at the start of a sentence,
in a bulleted list. Never "Diconium", never "DICONIUM" unless the whole headline is legitimately in
CAPS and under the character limit.

**Primary headlines** may be CAPS **when they are 30 characters or fewer**. Above 30 characters they
are lowercase. Count the characters — this is a hard rule from the guide, not a feel.

**Secondary headlines are always lowercase.** **Body copy is always lowercase.**

**If a document mixes long and short headlines, drop CAPS altogether** and set everything lowercase.
Consistency beats the device.

CAPS are an active identity choice for short, punchy key messages. They are not a way to add emphasis
to an ordinary heading.

## Line height and tracking

Line height: 1.05 for large CAPS display, 1.15 for headlines, 1.5 for body, 1.65 relaxed.

Tracking: −0.02em tight, 0 normal, **0.04em on CAPS headlines**, 0.12em on overlines. CAPS need the
extra tracking — set without it they read as cramped.
