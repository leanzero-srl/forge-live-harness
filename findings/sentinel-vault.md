## BUGS TO FIX (ordered by severity)
Source: adversarial code audit (each adversarially verified) + harness live findings. `[code]` = code-verified; `[live]` = also confirmed live.

### Major
- **SV-M1 [code + LIVE ✓ confirmed] Hard-revert wholesale-overwrites the live page with the last-good body, discarding concurrent unrelated edits (TOCTOU).** `triggers.js:460-472` writes the full last-good ADF over `current.version+1` with no re-validation; decision based on the version read earlier but the overwrite lands on whatever is current at write time. **LIVE: a save that added a legitimate "NEWSECTION" heading AND violated max-length → revert kept KEEPME but DESTROYED NEWSECTION (`revert-destructive.spec.ts`).** Fix: surgical revert (remove only violating nodes), or re-validate the re-read current + abort if it now passes / version changed.
- **SV-M2 [code] Restore/revert notifications fire even when the page write never succeeded → owner told content "restored/reverted" while still tampered.** `triggers.js:165-167` queue + `195-199` dispatch "regardless of write success"; if all retries 409 (anyChange false) or a non-409 break, a `content-removal`/`section-reverted` notice still fires. Fix: gate dispatch on `anyChange`/`putRes.ok`; queue notifications only after a confirmed write. (Merged duplicate.)
- **SV-M3 [code] Loop-guard fails OPEN when the app's own account id can't be resolved → unbounded revert/version-churn loop.** `triggers.js:33-47`/`111-114`: a non-ok `/user/current` (401/403/429/5xx) leaves `systemAccountId` undefined → guard skipped → app's own `asApp` re-saves no longer short-circuited; in revert mode each revert is a new unchecked version with `lastGood<version` → reverts forever. Fix: fail-CLOSED on unknown account (skip body-mutating writes); log + cache negative; gate revert on optimistic concurrency.
- **SV-M4 [code + LIVE ✓ confirmed] min-length/max-length count `[embedded object]` placeholders as ~19 chars each → an image/macro-only page passes min-length.** `rules-engine.js:67-80` via `extractPlainText` (`doc-surgery.js:751-754`). **LIVE: a page of 8 macro nodes + zero prose PASSED a min-length:100 rule (`minlength-placeholder-SV-M4`).** Fix: measure length from real authored text only (exclude media/extension placeholders).
- **SV-M5 [code + LIVE ✓ confirmed] Owner edits to a sealed section are never re-baselined → a third party's unrelated page save reverts and destroys the owner's legitimate edits + posts a false "section-reverted" blaming them.** `triggers.js:339-340,378-411`: owner-edit branch `continue`s without updating snapshot/hash; later non-owner save sees `liveHash != contentHash` → `replaceSectionBody` to the stale snapshot. **LIVE: owner edited section V1→V2 (stood; snapshot stayed stale at V1); a subsequent non-owner save reverted the section to V1, destroying the owner's V2 (`sealed-section.spec.ts`).** Fix: re-baseline in the owner-edit branch when `liveHash != contentHash && lockedBy===ctx.atlassianId` (like the grant branch).
- **SV-M6 [code] Sealed-media restore relies solely on currentVersion-1 → a second edit (or trigger lag) after removal permanently bypasses protection.** `triggers.js:265-277`: no durable ADF snapshot of the media; if the version still containing the media isn't exactly currentVersion-1, restore returns [] and the page is left tampered. Fix: persist a media snapshot at seal time (as section seals do) and restore from it.
- **SV-M7 [code] Section tamper-detection uses a 32-bit FNV-1a hash → second-preimage is trivial; a sealed section can be edited without revert/notification.** `doc-surgery.js:721-729` + the only check is `liveHash === seal.contentHash` (`triggers.js:379-380`), no byte/structural compare. Fix: wide/cryptographic digest (SHA-256 of canonical JSON or HMAC) or structural compare against the stored snapshot.
- **SV-M8 [code] sealArtifact rejects re-sealing with "already sealed by another user" when the existing seal is EXPIRED but not yet swept.** `sealing/actions.js:178-184` guard has no `expiresAt` check; `expirySweepTask` only notifies, never deletes. Fix: treat an expired record as absent + delete it before re-sealing.

### Minor
- **SV-m1 [code] Advisory validation comment can be posted multiple times (dedup marker written AFTER the side effect, no CAS).** `triggers.js:429` checks `wasVersionChecked` but marks only at the end (448/485) while the comment posts at 453-456 — TOCTOU on duplicate `updated:page` events. Also undefined `version` bypasses dedup. Fix: claim the version atomically right after the gate, before any side effect.
- **SV-m2 [code + LIVE ✓ confirmed] Gate status stuck on 'failed' after an auto-revert (gate+revert both on): state never reconciled to the restored compliant content.** `triggers.js:458` then `460-483` reverts; app re-save short-circuited so `runValidationPhase` never re-runs → inline-panel/doc-ribbon permanently show "Issues found". **LIVE: violating edit → content reverted to compliant (page v3) but gate state stayed `failed` (for v2) (`gate-revert.spec.ts`).** Fix: after a successful revert write `{state:'passed', version:<new>}`, or treat state stale when `state.version !== current page version`.
- **SV-m3 [code] Manual "Validate now" fails OPEN: a page-read error returns passed:true → panel shows "All checks passed".** `validations/actions.js:79-82` catch returns `{passed:true}`; UI ignores `error`. Fix: return a distinct failure shape + render "could not validate".
- **SV-m4 [code + LIVE ✓ confirmed] required-macro uses unanchored `endsWith()` → an unintended macro (incl. the app's own nodes) satisfies the rule.** `rules-engine.js:45`. **LIVE: required-macro `extensionKey='section'` on a page whose only macro is a Sentinel sealed-section → reported COMPLIANT (`reqmacro-endswith-SV-m4`).** Fix: anchor (`extensionKey.split('/').pop() === key` or `endsWith('/'+key)`).
- **SV-m5 [code + LIVE ✓ confirmed] Heading rules collect headings from NESTED contexts (table cells, panels, sealed sections) → false hierarchy skips / over-counts.** LIVE: a page with a valid H1→H2 outline + an H4 inside a table cell was FLAGGED as a hierarchy violation (`heading-in-cell-SV-m5`). `rules-engine.js:56-66` via `collectHeadings` (`doc-surgery.js:768-788`) recurses with no type gate. Repro: outline H1,H2 + an H4 inside a table cell → false "skip from H2 to H4". Fix: scope outline to document-flow headings (don't descend into tableCell/panel/bodiedExtension).
- **SV-m6 [code + LIVE ✓ confirmed] Removed sealed-section re-insertion uses a stale originalIndex → wrapper dropped at the wrong position when blocks were added/removed above it.** `triggers.js:351-356` + `doc-surgery.js:684-692` only clamps. **LIVE: sealed @ index 1; deleted it + inserted 2 paragraphs at top → trigger re-inserted at the STALE index 1, BETWEEN the two new paragraphs instead of next to its original "TOP" neighbour (`sealed-section.spec.ts`).** Fix: anchor restoration to a stable neighbor / heading text, not a frozen absolute index.

## Live-repro constraints (code-verified; NOT reproduced live — honest, not flaky)
These remain `[code]`-solid from the adversarial audit, but reproducing them on the live app is impractical/out-of-scope for a deterministic suite. Reason per finding:
- **SV-M2** — needs ALL `writeDocBody` attempts to 409: a forced race inside the trigger's read→write window. Timing is uncontrollable via REST → would be flaky. Not attempted.
- **SV-M3** — needs `/user/current` to return 401/403/429/5xx during the trigger so `systemAccountId` is undefined. Can't force that failure from outside.
- **SV-M6** — sealed-MEDIA restore; needs attachment upload/versioning + the media-seal record + a precise version sequence. Setup not built (and partly resolver-side).
- **SV-M7** — 32-bit FNV second-preimage needs ~2³² `hashAdf` trials to match a sealed hash. Impractical to brute live; the weakness is structural (8-hex digest, no HMAC, only `liveHash===contentHash`).
- **SV-M8** — `sealArtifact`/expiry are resolver actions (bridge-invoked), not REST-reachable; would need a hook action that invokes them.
- **SV-m1** — needs duplicate `updated:page` delivery for the SAME version to trip the TOCTOU. Confluence event delivery isn't controllable.
- **SV-m3** — `validatePageNow` is a resolver + needs a page-read failure (5xx/trashed) during the call. Resolver-only + uncontrollable error.
